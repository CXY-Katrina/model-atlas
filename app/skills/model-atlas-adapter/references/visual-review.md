# 图示检视清单

主 agent 布局前阅读；图示 agent 在每轮检视时执行。适用于整个页面的所有拓扑、概览、展开图和详情，不限于用户圈出的局部。

先按 [Archify 集成约定](archify-integration.md) 验证实际使用了该工具、源/产物 hash 与回执匹配，再分别检查其独立 HTML 和 model-atlas 接入页面。只有自动检查回执而未看实际图像，或者只检查离线生成图而未检查网站展示，均不能 PASS。报告写入协作目录，不混进模型成果 docs。

## 检视方法

1. 按候选渲染清单打开实际页面，确认模型、源码指纹、构建版本和字体加载完毕。为自己使用独立浏览器 tab/page，记录 page id，避免与另一 agent 互相切换、拖动同一页面。
2. 查看全图确定完整性，再以可读比例逐区检视。至少覆盖仓库已有的桌面回归宽度（当前例子为 1440、1920、2048）、实际目标视口、明暗主题、详情开关及全部不同拓扑。若产品声明移动端支持，再加入相应窄屏；不擅自承诺移动端已通过。
3. 必须实际读取截图／浏览器画面，并配合 DOM/SVG 测量。把节点、文字、标题、边、箭头和背景分组放到同一坐标系；包含 zoom、pan 和 transform。源码 lint 或单张裁切图不能替代视觉检视。
4. 对曲线使用实际 SVG 路径／采样进行相交检测，并将 stroke、箭头包围盒、文字和安全间距算进去。边与自己的合法端口接触、跨分组边界垂直穿入是正常连接；沿边框长距离共线、无关节点被穿过、文字遮盖连接是缺陷。共享干线只在显式 fanout 中豁免。
5. 用候选来源截图和测量作为证据。若浏览器不可用，结论为 BLOCKED，相关覆盖项标记 NOT-RUN，不以“肉眼看代码没问题”写 PASS。

## V1. 内容尺寸与 padding

- 卡片允许不同宽度，文本左右 padding 使用相同公共 token；标题、正文和 shape 全部计入高度。不要将每个 block 拉成一样宽。
- 长标识符按合理断点换行或适度增宽，框随内容增高；`index slot_mapping`、`position_ids · future bound`、`block_indices` 的上下行不能贴边或出框。
- 代码块允许专用横向滚动，公式长行可控换行／局部滚动；它们不能撑破详情栏，更不能借全画布裁切隐藏溢出。
- 所有背景分组在同一层级使用统一左右留白，基于成员可见外边界而非网格占位。明确边框宽度和测量容差（例如 CSS px 的 1px），不混淆 border 与 padding。
- mask 矩阵图给出 query／key 轴、token／block 粒度、每个 query group 的归属及 selected／non-selected 图例；色块和括号不遮文字，不用没有语义依据的装饰矩阵替代真实选择逻辑。
- V PATH 只有窄 tensor 时不保留 K PATH 权重列那样的宽底框。attention score/backend pipeline 不因远处 V 支路或外部输入继承整幅画布宽度。
- 外部输入可调整到算子另一侧以压缩无效空白，例如把主 KV cache 的 slot_mapping／block_table 放左侧，让 Indexer 靠近；先检查左侧连接和节点碰撞。

## V2. 连线优先级

按以下顺序选择走线：语义正确且箭头清楚 → 不穿节点／标签且尽量无交叉 → 可以直连就直连 → 最少转折 → 较短长度 → 同类连接对称。不宣称数学意义的全局最优。

- 上下节点可对齐时使用直线。允许移动目标 block 或端口来消除小幅 S 弯，例如 paged K → QK、P → PV、router logits → routing 和 Index K 链。
- 多输入目标的端口可按角色布局；为了让每条边“对称”而凭空拐弯不合格。必须弯折时使用一致圆角和足够前后直线段，避免突兀硬拐和极短折返。
- 对称分支围绕所属源或目标的中心轴布置；两侧相同高度开始转弯、相同高度合入、对应端口等距、半径一致。特别检查 KV cache 的输入／输出和 MoE routed/shared 合流。
- 两侧干线高度相同且线宽一致，共享段只绘制一次，防止重复描边或白色描边叠加造成粗细差。数据／weight／external 各自风格一致。
- 分裂点使用统一干线，不能用若干独立近似曲线制造错位接缝。每个分支末端均有可见箭头，包括 Q、K、V；转角到目标之间留足箭头长度和安全距离。
- 远程 V 输入若与 P 或 index 连线交叉，可走右侧独立通道；让通道贴近相关图，而非为它保留一屏空白。改变走线路径不能改变张量的生产者和消费者。

## V3. 框、文字、连线互不遮挡

- 节点和标签是障碍物，不通过提高 z-index、添加背景色遮住线、overflow hidden 或擦除线段来伪装“已避障”。预留独立标题带和连接通道。
- 保留有意义的 Q PATH、K PATH、V PATH、LIGHTNING INDEXER 等分组说明；并列分组标题使用同一文字基线和上边距，比较实际文字位置而非仅框的 top。
- 每个有语义的背景框有名称。背景框必须包住所声明的内部节点和外部输入卡片（若卡片有意放在外部，明确归属并留出连接通道）；分组背景不能遮住相邻分组，例如 Indexer 覆盖 V PATH。
- 不相关的线不能穿过卡片、沿卡片边框走或与虚框共线。特别检查 paged V 横线与 block_indices、router logits 线与 routed expert weights、Add 上沿与输出连线。
- 线需要穿过分组边界时尽量垂直穿越，离标题和圆角保持距离。不同连线的真正交叉尽量通过布局消除；不可避免时明确采用不被误认成连接点的跨线表达并记录原因。

## V4. 密度与交互

- 逐层收紧无意义空白：输入分叉不跨越过长空带，权重箭头不能短到只剩箭头，支路间距不以整列无内容补齐。
- 若全部内容以可读字号能容纳于当前视口，就禁用平移、grab 光标和拖动提示，并重置先前 pan 偏移。超出视口时才允许受限平移／滚动；不要缩成不可读的“一页图”。
- 展开／收起、切层、切模型、切主题、打开／关闭详情、hover/pin、窗口 resize 后重新检验路由和可见性。图的对齐不能在节点 remount 后丢失。
- 渲染截图说明是否有意平移／裁切；验收完整性至少有总览或覆盖完整范围的一组截图。

## 输出要求

每项 finding 写出规则编号、场景、节点／边 id、文件位置、截图或测量证据、建议约束和复查结果。说明实际覆盖了哪些场景；未检查的范围不能写“全页通过”。按文档契约独立出具 PASS／CHANGES_REQUIRED／BLOCKED。
