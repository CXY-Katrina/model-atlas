# 仓库适配约束

本文件描述需要保持的分工。实际接口以当前 checkout 的 `docs/model-extension.md`、`app/models/registry.ts` 和测试为准；路径变更时更新适配方式，不把旧结构强加给仓库。

## 模型模块

- 新模型位于 `app/models/<model-id>/`。入口提供当前 `ModelDefinition` 所需的 id、name、resources、facts、View 和可选 Reference，并在模型注册列表注册。
- View 自主管理层分类、展开、详情与模型特有交互，通过 `onExpandedChange` 通知公共页面。新增模型通常只新增模型目录、注册项、研究文档和测试。
- 可参考现有模块拆分 config、sources、data、operators、formulas、evidence、diagrams、details、layout；按新模型规模选择文件，不机械复制 MiniMax 的完整文件树。
- 复用 `app/graph/` 的节点、连线、对齐和画布能力，复用详情选择状态。共享层保持模型无关；新增 OpKind 或 dtype 时验证确有需要并回归现有调用方。
- 新增模型的结构图必须执行 [Archify 集成约定](archify-integration.md)。`app/graph/` 可继续服务现有图与页面辅助交互，但不能据此跳过 Archify 或用另绘的图替换其交付产物。模型 View 接入生成 HTML，外围的公式/源码详情仍使用模型模块。
- 模型不必有 Dense/Sparse 双分类、MoE、Indexer 或视觉支路。不要预建“即将支持”占位选项，把测试 fixture 留在测试入口。

## 样式与维护

- 公共颜色、文字、边框、线、间距、padding、圆角与字号从 `styles/tokens.css` 读取，明暗主题使用语义 token。模型特有布局放在自己的 CSS。
- 使用 `:where([data-model="<model-id>"])` 隔离模型选择器。作用于根 `.atlas-app` 时使用 `.atlas-app:where([data-model="<model-id>"])`，避免错误的后代关系。
- 拓扑专用端口和分流／合流约束留在模型图示定义，公共 `GRAPH_GEOMETRY` 管理通用几何常量。更改公共常量必须检查所有现有模型，不以修一个图破坏其他图为代价。
- 卡片大小由内容和统一 padding 决定；布局列的可用宽度不应强迫卡片撑满。分组边界从实际成员和必要的内部路由空间计算，不能继承无关兄弟分组的空列。
- 当同一缺陷反复出现，收敛节点端口、网格约束和连线算法；删除本次改动造成的失效／重复规则。仅清理已证明无用的代码，保留他人的改动。

## 把研究内容渲染出来

研究文档不是交付的唯一载体。用户应能从新模型入口看到：Archify 生成的概览及子图、算子输入输出与权重、公式及符号定义、对应源码位置与固定版本、实现差异与必要限制。资料链接属于当前模型，切换模型不遗留上一模型的标题、详情或帮助弹窗。只消费模型知识成果与验收产物；spec、handoff、review、responses 和日志不进入网站内容或构建资源，文档分类以 [文档契约](document-contract.md) 为准。

允许概览省略内部步骤，但展开图与详情必须清晰指向完整说明。结构化证据可供文档和页面共同消费；若维护两份表示，测试和语义 review 必须检查它们一致。

## 测试策略

- 从 package scripts 发现现有检查方式，不为套用技能换构建工具或添加图表库。
- 在已有注册与 shell 测试上补新模型入口、非法／重复 id、URL、历史导航、主题保留和状态重置检查。
- 每种不同拓扑都补节点／边／来源映射测试；公式解析通过不代表数学正确，必须另做 shape 与语义校验。
- 每个修复的重叠、短箭头、错位或溢出问题补可观测回归断言，优先 DOM/SVG 几何和交互结果，而不是只匹配 CSS 源码字符串。
- 公共改动回归现有模型各类展开图；为新模型添加自己的浏览器覆盖，已有 MiniMax 测试通过不能替代新模型验收。

## 服务和发布

复用服务前核验实际页面与工作区。启动服务后返回真实可访问 URL；重构源码的本地预览与已发布 Pages 是两个不同版本。

提交和部署需要本次用户授权。读取仓库工作流确认触发分支，不默认将功能分支合入 main。若推送目标不触发 Pages，说明需要的额外动作并请求方向。检查部署对应的 head SHA，而不是把上一次成功工作流当作本次成功。静态部署验证相对资源／base path，避免本地正常但 Pages 空白。

授权粒度分别判断：本地提交不等于允许 push，push 不等于允许 merge 或另行部署；用户要求的正常工作流已明确包含的自动效果（例如推送部署分支触发 Pages）按该授权执行并说明。
